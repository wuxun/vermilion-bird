# GUI 交互架构

**状态**：Codex-like Shell V2 已落地
**设计基线**：Codex 式项目/任务工作台，而非传统聊天窗口叠加管理弹窗

## 产品主线

```text
统一工作线程 → 可选持久目标 → 计划/执行/审批 → 验收交付物 → 继续修订 → 保存为工作流
```

GUI 必须围绕用户目标和交付结果组织信息。`WorkItem` 是用户理解的任务，
`Run`、checkpoint、effect 和底层事件属于按需展开的执行细节。

参考资料：

- <https://openai.com/index/introducing-the-codex-app/>
- <https://openai.com/codex/get-started/>

## 信息架构

### 应用壳层

主窗口采用统一的暖白朱红壳层：

- 单一左侧栏承载新建对话、工作概览、历史搜索、最近会话和设置；
- 不再叠加“窄导航栏 + 会话侧栏”两级导航；
- 当前任务标题固定在内容顶栏，低频操作进入省略菜单；
- 对话正文限制最大阅读宽度，宽屏留白用于降低扫视负担；
- Composer 固定在底部，文件、Skills 和 MCP 通过 `＋` 渐进展示；
- 模型选择、发送和停止属于 Composer 自身，不再拆成独立状态栏；
- 工具调用默认折叠，只保留名称与执行状态。

视觉系统使用暖白、暖灰组成四级表面，文字使用暖炭黑。朱红承担品牌、主动作、
选中态和需要注意的状态，语义成功、警告、信息仍保留各自颜色。红色不得大面积铺底，
确保长时间使用的舒适度和正文可读性。不得复制 OpenAI Logo、Codex 名称、原始图标
或专有素材。

### 统一工作线程

- **对话是唯一内容入口**：临时讨论、即时问答和复杂执行都从同一个 Chat 开始。
- **目标是对话的渐进能力**：需要持续执行时，将当前对话设为目标并保留已有上下文。
- **工作概览是聚合视图**：跨对话查看执行进度、审批、自动化更新和交付物，不建立
  第二套输入与历史体系。
- **设置**：模型、MCP、Skills、Scheduler 和高级执行中心。

工作概览嵌入主窗口。点击任一最近对话返回统一工作线程；目标状态和“查看进展”位于
当前对话 Composer 上方。
高级执行中心保留 Run、重放、恢复和副作用对账能力，但不再作为普通用户的一级入口。

### 任务工作区

任务详情收敛为三个区域：

1. **进展**：目标、预期交付、结构化计划、执行活动、待审批动作和交付结果。
2. **交付物**：打开、导出、接受、要求修改和拒绝。
3. **详细信息**：上下文、计划表、资源权限和 Run 记录。

计划确认和动作审批以“待你处理”卡片出现在进展页。底部只突出一个与当前状态匹配的
主操作，暂停、恢复、重试、取消和高级执行记录放入“更多”菜单。

任务范围分为“全部任务 / 进行中 / 待你处理 / 新结果 / 已结束”。“待你处理”只包含会
阻塞目标推进的计划确认、审批、失败和强制验收；普通自动化结果进入“新结果”，不计入
一级导航待办。`none` 策略的结果只保留在任务时间线和交付物列表。

## 关键交互规则

### 设置目标

普通对话可以随时“设为目标”。表单一次展示：

- 目标和验收约束；
- 可选标题；
- 工作目录；
- 预期交付物；
- 是否立即执行。

升级后复用当前 `conversation_id` 和完整消息历史。用户可以立即执行，也可以只保存目标，
稍后继续输入或从工作概览启动。工作概览直接新建目标时，系统同时创建对应对话。

### 状态主操作

| 任务状态 | 主操作 |
|---|---|
| 草稿、待执行 | 开始执行 |
| 存在待审批动作 | 处理审批 |
| 存在待确认计划 | 确认执行计划 |
| 已暂停 | 继续执行 |
| 失败且可重试 | 重试任务 |
| 已完成且有交付物 | 查看交付物 |
| 执行中、正在暂停、正在取消 | 展示状态，不提供误导性主操作 |

### 任务后续协作

终态任务保留任务输入框。用户可以追加要求或提出修改意见，系统在原会话、
原 `WorkItem` 和既有资源边界内创建新的根 Run，并生成新的可验收交付物。
运行中的任务暂不接受并发 follow-up，以免产生顺序不确定的上下文和副作用。
