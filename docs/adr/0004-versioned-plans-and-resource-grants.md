# ADR 0004：版本化计划与资源级授权

- 状态：Accepted
- 日期：2026-07-28

## 背景

任务只有自然语言目标时，用户无法确认执行步骤是否发生变化；仅按抽象能力审批时，
“允许写文件”也无法表达只允许写入某个目录、只允许访问某个域名或只允许向某个目标
发送消息。随着任务恢复、自动化和多 Agent 执行增加，这两类模糊边界会放大误执行风险。

## 决策

### 计划

- `PlanRevision` 是一个 WorkItem 下按版本递增的计划快照。
- 每个修订包含有序 `PlanStep`、依赖、预期 Artifact 类型和所需能力。
- 新修订不会覆盖旧修订；批准新修订时，旧批准版本标记为 `superseded`。
- 只能批准最新修订，避免用户误将过期草稿恢复为执行基线。
- 只有批准版本会注入任务执行请求；草稿仅用于审阅。
- 步骤运行状态可更新，但计划定义、依赖和版本不在原记录上修改。

### 授权

- `ResourceGrant` 同时绑定能力、资源类型、规范化资源、任务或工作流范围、有效期。
- 资源类型首批只支持目录、域名和消息目标。
- 工具只有在所有待审批能力都能提取出明确资源并逐项匹配时，才可免重复审批。
- 相对路径按任务工作目录规范化；目录匹配允许子路径，但拒绝路径逃逸。
- 域名匹配允许同一域的子域，不接受字符串后缀伪装。
- `process` 和 `secrets` 不通过普通资源授权自动放行。
- `once` 授权首次匹配后立即撤销；授权支持到期和人工撤销，并记录最后使用时间。

## 数据与迁移

schema v5 新增：

- `plan_revisions`
- `plan_steps`
- `resource_grants`

计划版本号在单个 WorkItem 内唯一，步骤位置在单个修订内唯一。活动授权按任务/工作流、
能力、资源和范围去重。升级沿用 WAL 一致备份和失败恢复机制。

## 结果

优点：

- 用户可在执行前看到并批准稳定计划；
- 任务恢复时可知道采用了哪个计划版本；
- 常用且边界明确的动作无需逐次审批；
- 权限变化可撤销、可过期、可审计。

代价：

- 工具参数必须能映射为明确资源，否则仍需审批；
- 计划步骤状态目前由应用显式更新，后续 WorkflowDefinition 需要自动投影；
- 工作流范围授权要等 WorkflowDefinition 落地后才能完整复用。
