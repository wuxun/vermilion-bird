# ADR 0012：对话附件使用可审计的 ContextResource

**状态**：已接受  
**日期**：2026-07-31

## 背景

Composer 需要支持文件和目录上下文。直接把路径拼进 Prompt 无法表达资源是否仍存在、何时
发生变化、是否属于某个 WorkItem，以及用户是否允许把内容交给所选模型；把全文复制进
消息又会污染聊天记录、数据库和导出内容。

## 决策

1. 文件和目录建模为独立 `ContextResource`，先归属 conversation，设为目标后再关联
   WorkItem。
2. 数据库只保存规范化路径、类型、大小、修改时间、snapshot hash、状态和外发策略，
   不复制文件正文。
3. 用户通过文件选择器或拖放添加资源，视为允许把其可读取内容提供给当前选择的模型；
   `local_only` 资源只持久化，不注入模型上下文。
4. 每次读取重新计算 snapshot；源发生变化时继续使用当前内容，但在上下文中明确标记。
5. 文件内容作为“不可信参考数据”注入，不得被解释为系统指令、授权或工具调用要求。
6. 目录跳过隐藏目录、隐藏文件、符号链接和二进制内容，并设置文件数、manifest 和字符预算。
7. 移除采用软删除，保留本地审计事件，但后续请求不再注入。

## 结果

- 对话消息保持干净，恢复执行时可以重新构建同一来源边界；
- 用户可以在 Composer 中看到并移除当前上下文；
- 资源来源和 WorkItem 关系可追溯；
- 当前版本仅内联常见文本和代码格式。PDF、Office、图片和音视频解析在 Artifact/Context
  适配器阶段实现，不在基础模型中硬编码。

## 后续约束

- 外部模型调用前必须经过 `ExternalTransferPolicy`；
- GUI 不直接读取文件，统一通过 `ContextResourceService`；
- Product Event 不得记录路径、文件名或正文；
- 未来的内容快照必须进入受控 blob store，不能写入聊天消息或通用 metadata。
