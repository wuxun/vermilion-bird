# ADR 0013：Artifact 使用不可变版本与显式派生链

**状态**：已接受  
**日期**：2026-07-31

## 背景

用户对交付物提出修改后，如果继续覆盖原记录，就无法回答“这个版本由什么反馈产生”、
“哪次 Run 生成了它”以及“此前接受或拒绝的是哪个版本”。任务恢复、评估和未来的版本 Diff
也会失去可靠输入。

## 决策

1. 已创建的 `Artifact` 不允许原地修改；修订和派生都创建新记录。
2. 同一逻辑交付物共享 `lineage_id`，使用单调递增的 `version` 标识版本。
3. 新版本通过 `parent_artifact_id` 指向直接父版本，并用 `relation` 区分原始、修订和派生。
4. 由用户反馈触发的版本通过 `source_feedback_id` 关联对应的不可变反馈事件。
5. 文本内容在创建时自动计算 SHA-256；外部文件仍可携带调用方提供的 checksum。
6. 同一 WorkItem 的后续主结果默认修订上一主结果，而不是创建无关系的平行交付物。
7. GUI 和时间线始终显示版本号；预览和 Diff 在后续独立切片实现。

## 不变量

- parent 和 source feedback 必须属于同一 WorkItem；
- 非原始 Artifact 必须存在 parent；
- 旧版本的正文、来源 Run、checksum 和 metadata 不被新版本覆盖；
- 幂等键仍然代表一次确定的产物创建，重复调用返回同一版本；
- Product Event 只记录类型、关系和版本号，不记录交付物正文。

## 结果

Artifact 现在可以支撑可追溯修订、验收率按版本计算、版本预览/Diff，以及未来从高质量
交付物沉淀 Workflow 的数据闭环。
